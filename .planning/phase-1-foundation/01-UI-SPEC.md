## Spacing Scale

8-point scale (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon-to-text gap, tight inline spacing |
| sm | 8px | Compact stack inside form rows (label↔input gap) |
| md | 16px | **Default** spacing between form fields, between cards, between paragraphs |
| lg | 24px | Section padding inside cards, gap between form sections (e.g. "credenciais" vs "consentimentos") |
| xl | 32px | Page padding (mobile), gap between header and main content |
| 2xl | 48px | Major section breaks, page padding (desktop ≥ md breakpoint) |
| 3xl | 64px | Hero/empty-state vertical breathing room |

**Touch target floor:** 44px (REQ CAT-08 — applies even though CAT-08 is Phase 3, this is locked at the design-system level so all phases inherit).

**Form field height:** 48px on mobile (≥44 with folga). Buttons: 48px primary, 44px secondary minimum.

**Exceptions:** Inline icon-only buttons inside dense admin tables (Phase 7+) may be 40px square, but Phase 1 has none — no exception applies for Phase 1.

## Typography

Exactly **4 sizes** and **2 weights** (locked by checker dimension 4):

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Caption / Help / Form error | 14px | 400 (regular) | 1.5 | Geist Sans |
| Body / Form label / Form input / Button | 16px | 400 regular OR 600 semibold (button + label) | 1.5 | Geist Sans |
| Section heading (h2) | 20px | 600 semibold | 1.2 | Geist Sans |
| Page heading (h1) | 28px | 600 semibold | 1.2 | Geist Sans |
| **Brand wordmark only** ("Doces Valentina" in header + auth hero) | 28px on mobile / 32px on ≥md | 500 medium (Fraunces variable) | 1.1 | Fraunces (display) |

**Justification:** 16px body is the floor required by CAT-08 + FEATURES research 7.2 (clientela mais velha). 14px allowed only for low-priority help/caption text where the user's primary attention is on the adjacent 16px field. No 12px allowed anywhere in Phase 1.

**Anti-rules:**
- No font weight 300/light anywhere (legibility for older readers).
- No italic in body or labels (legibility + screen-reader friendliness).
- No all-caps headings (loses cedilha + tilde character distinctness in PT-BR).
- No `font-stretch` or condensed weights.

## Color

**60 / 30 / 10 split applied as default ("nenhuma campanha ativa" — Phase 6 will override via CSS vars):**

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant 60% (background) | `--color-background` | `#FFFBF7` (creme quente) | Body background, page surface |
| Secondary 30% (surface) | `--color-surface` | `#FFFFFF` | Cards, form containers, dialog body |
| Secondary 30% (border) | `--color-border` | `#F1E8DD` | Card borders, input borders, divider lines |
| Accent 10% (brand) | `--color-accent` | `#C2410C` (rose-orange amarronzado, doce-de-leite) | **See "Accent reserved for" below** |
| Accent on accent | `--color-accent-foreground` | `#FFFBF7` | Text on top of accent (contrast 6.4:1, AAA) |
| Destructive | `--color-destructive` | `#B91C1C` | Destructive actions ONLY (see list below) |
| Destructive foreground | `--color-destructive-foreground` | `#FFFFFF` | Text on top of destructive |
| Foreground (text) | `--color-foreground` | `#1F1611` (marrom muito escuro, não preto puro) | All body text (15.8:1 vs background, AAA) |
| Foreground muted | `--color-foreground-muted` | `#6B5B4F` | Help text, captions (5.1:1 vs background, AA Large + AA normal) |
| Focus ring | `--color-ring` | `#C2410C` at 50% opacity, 2px outside | Keyboard focus ring on every interactive element |
| Success (no UI in Phase 1, declared for forward-compat) | `--color-success` | `#15803D` | Reserved for Phase 4 confirmações |

**Accent reserved for** (explicit list — never "all interactive elements"):
1. Primary CTA buttons (`Criar minha conta`, `Entrar`, `Enviar link de recuperação`, `Salvar nova senha`, `Baixar meus dados em JSON`)
2. Active link underline + visited link state
3. Brand wordmark "Doces Valentina" in header
4. Focus ring on all interactive elements
5. Selected radio/checkbox fill
6. Progress indicator (e.g. step 1 of 2 dot in cadastro stepper)

**Accent NOT used for:** secondary buttons (use `surface` + `border`), inline links inside body copy (use `foreground` + underline), informational alerts (use neutral `surface` + `border` with icon), card backgrounds, hover states of secondary controls, status badges (Phase 1 has no status — defer to Phase 4).

**Destructive reserved for:**
1. The "Excluir minha conta" button on `/minha-conta/excluir`
2. The 1-line confirmation banner above that button ("Essa ação não pode ser desfeita.")
3. Form-level error states when the submission fully fails (e.g. "Token expirado")
4. Email bounce indicator on `/admin/auditoria` rows where `email_invalid=true` (NOTIF-04 lays the groundwork; Phase 1 just renders the column)

**Destructive NOT used for:** field-level validation errors (use `--color-foreground` + small icon + 14px caption), inline cancellation links, anti-enumeration generic messages.

**Contrast verified (WCAG AA, against `#FFFBF7` background unless noted):**
- `#1F1611` foreground: 15.8:1 (AAA)
- `#6B5B4F` foreground-muted: 5.1:1 (AA normal, AA Large)
- `#C2410C` accent: 4.6:1 (AA normal — passes for 16px+ text and UI components per WCAG 1.4.11)
- `#B91C1C` destructive: 5.4:1 (AA normal)
- White on `#C2410C`: 6.4:1 (AAA)
- White on `#B91C1C`: 7.5:1 (AAA)

**Dark mode:** Phase 1 declares dark-mode tokens but does NOT enable a system-driven toggle. Reason: clientela majoritária 50+, opens from WhatsApp link in daylight; dark mode adds bug surface for zero validated benefit in Phase 1. Reactivate decision in Phase 6 if sazonalidade demands. Tokens for forward-compat:
- `--color-background` dark: `#1F1611`
- `--color-foreground` dark: `#FFFBF7`
- `--color-surface` dark: `#2A1F18`

## Interaction & Accessibility Contract

Locked rules (apply to every Phase 1 surface; checker validates):

| Rule | Specifics |
|------|-----------|
| Touch target floor | 44×44px minimum hitbox on every clickable element (buttons, links, checkboxes, radios). Visual size can be smaller (e.g. 20px checkbox graphic) but the wrapping `label`/`button` must be ≥44px. |
| No hover-only states | Every state reachable on hover must also be reachable on focus + on tap. Tooltips with critical info forbidden — info either inline or in `aria-describedby` text. |
| Focus visible | 2px `--color-ring` (orange at 50%) outside outline on every focusable element. Never `outline: none` without replacement. |
| Color independence | Status never communicated by color alone — always paired with icon (lucide) + text. Phase 1 has minimal status, but the rule locks for downstream phases. |
| Form labels | Every input has an explicit `<label>` (not just placeholder). Placeholder used only as a sample value, never as the label. |
| Error association | Field errors use `aria-describedby` pointing to the error message; error message is rendered immediately below the field in 14px caption + foreground color (NOT destructive red — destructive reserved for catastrophic states). |
| Required indicator | Required fields marked with " *" after label + `aria-required="true"`. Reserved color is `--color-foreground` (not red asterisk). |
| Submit feedback | After form submit: button shows loading state ("Enviando..."), preserves width. On success: page navigation OR sonner toast (not both). On error: focus moves to the error summary at top of form. |
| Keyboard nav order | Logical top-to-bottom, left-to-right. Tab from email → senha → +18 checkbox → termos checkbox → submit. No `tabindex` > 0 anywhere. |
| Mobile viewport | `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` (cover to handle iOS safe areas). |
| Sticky CTA on long forms | Cadastro step 2 has 5+ fields — primary CTA `Criar minha conta` is sticky at bottom of viewport on mobile (max-width to avoid keyboard overlap), normal-flow on ≥md. |
| Autocomplete attributes | Email: `autocomplete="email"`. Senha: `autocomplete="current-password"` (login) / `autocomplete="new-password"` (cadastro/redefinir). Telefone: `autocomplete="tel"`. Nome: `autocomplete="name"`. |
| Inputmode hints | Email: `inputmode="email"`. Telefone: `inputmode="tel"`. |
| Sonner toast position | Top-center on mobile, top-right on ≥md. Duration 5s for success, 8s for error. Always dismissable. |
| Generic auth messages (AUTH-07) | All sensitive flows return the exact same message regardless of email existence. No 200/404 distinction. No timing leak (server-side delay normalizes timing). |

## Mobile-First Layout Contract

| Aspect | Mobile (<md) | Desktop (≥md, 768px) |
|--------|--------------|---------------------|
| Page max-width | 100% with `px-xl` (32px) | `max-width: 480px` for auth/LGPD pages, centered with `py-2xl` (48px) — auth surfaces stay narrow even on desktop because they read better as a column |
| Admin shell max-width | 100% with `px-md` (16px) | `max-width: 1200px` content + 240px sidebar (Phase 7 expands) |
| Stack direction | Vertical only | Vertical — Phase 1 has no horizontal multi-column form |
| CTA placement | Sticky bottom on long forms (cadastro step 2, redefinir senha) | In-flow at end of form |
| Header | 56px, brand wordmark (Fraunces) left, "Sair" right when logged | 64px, same alignment |

Reason for narrow desktop: the auth shell is a sequential, low-density interaction. A full-width form on desktop reads worse and looks generic. Narrow column with hero microcopy ("Vamos começar com seu email") makes it feel like a hand-written page.

## Brand & Voice Guardrails (locked from PROJECT.md + FEATURES research)

These must be applied by every text rendered in Phase 1:

1. **Voz da mãe / vizinha** — usa "a gente" (não "nós"), "tá" (não "está") em copy informal de feedback (toast, success), "você" sempre (nunca "o usuário", "o cliente").
2. **Sem jargão técnico** — não usa "autenticar", "validar", "processar", "credenciais". Usa "entrar", "confirmar", "salvar", "senha".
3. **Sem inglês** — exceto siglas técnicas inevitáveis (JSON no botão de export — explicar entre parênteses se necessário).
4. **Sem all-caps** — perde acentuação. "ENTRAR" vira "Entrar".
5. **Sem ponto final em CTAs** — "Criar minha conta" não "Criar minha conta."
6. **Mensagens de erro orientam ação** — não só "Erro 500". "Tenta de novo em alguns segundos. Se continuar, escreve pra dpo@..."
7. **Anti-enumeration messaging** — todas as mensagens em fluxos sensíveis (esqueci, cadastro com email existente — exceto AUTH-03 que é INTENCIONALMENTE leak controlado para reduzir cadastros duplicados em clientela mais velha) usam o mesmo template.
8. **Brand wordmark** — sempre "Doces Valentina" (com cedilha do "ç" implícito em "Doces"; não usar "Doces da Valentina" ou variantes), Fraunces 500, accent color para o "V" maiúsculo opcional em headers grandes.
